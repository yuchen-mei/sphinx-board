## Board measurements

| Area | Measurement |
|---|---|
| Assembly and startup | Inspect polarity, socket orientation, solder joints, default output inhibition, AUX, independent U901 3V3_CTRL, and USB/Pico supply separation with the ASIC absent. Verify a cold board defaults OFF, while Pico boot on an already active board does not change outputs. |
| ON/OFF and protective faults | Capture U903 P03 RUN_SET, RUN_LATCH, HW_FAULT_N, and rail enables. Exercise ON/OFF, STOP, control brownout, asserted eFuse fault, Core/I/O OVP, and temperature protection. A cleared run latch must never set again without explicit authorized startup; STOP cannot be overridden by a set pulse. Power commands and protective trips preserve U903 P02's reset request. |
| Pico independence | After a successful command, halt firmware, disconnect USB, reboot Pico, and remove only Pico power. With valid 12 V, verify retained rail/reset requests, unchanged regulator configuration, no bus clamp/back-power effect, and read-only reattachment. Perform tests with reset both released and asserted. |
| Input interruption | With USB both present and absent, measure VIN12, AUX5V, 3V3_CTRL, VIN12_VALID, eFuse FLT, RUN_LATCH, and output rails. Distinguish retained configuration, regulator-only POR, control brownout, and eFuse faults. Full input loss/discharge must default OFF on return. A retained latch alone does not prove retained PMBus configuration. |
| Hot startup | Heat U1001 before applying input. Across supply-ramp and temperature corners, measure detector readiness against the R1001-selected supervisor delay and verify no ON attempt enables the rails before hardware fault qualification. TMP302 §9 states functional readiness within 35 ms after VS reaches 1.4 V; test the complete circuit, including nonmonotonic ramps. Cooling cannot generate a start pulse. |
| Failed startup | Verify an unconfirmed commissioning profile, incomplete discharge, configuration mismatch, active protective fault, or failed latch readback leaves both supplies disabled. Confirm there is no automatic set-pulse retry and no inserted reset request. |
| Diagnostic warnings | Exercise PG loss, ordinary undervoltage/voltage deviation, PMBus warning status, USB inactivity, malformed commands, and telemetry read failures. Confirm observed warnings do not change power or reset requests. A lack of polling is not itself a fault and does not provide a complete event log. |
| Current and temperature policy | Confirm routine Core/I/O budgets and the 10 A target are warnings, not software shutdown thresholds. With Pico absent, verify the regulator's commissioned OC/OV/OT response, independent Core OVP, U1001 temperature trip/hysteresis, and U1002 I/O OVP threshold/latency. Record actual tolerances; do not claim a 14 A/100 ms hardware limiter or exact 2.025 V trip. Use a suitable load with the ASIC absent. |
| I/O enable | Measure EN relative to local VIN during cold start, rapid input loss, and command transitions. Include SS/TR and the intended temperature range. |
| Regulation | Use a local load to measure 0.30, 0.50, 0.75, 1.00, and 1.20 V at light load and increasing current, including the 10 A continuous design target. Record operating temperature and protection settings. |
| Range changes | Verify a scale-changing SET checks state, disables rail requests, confirms discharge/readback, and restores the prior requests only if the existing latch survives. There must be no RUN_SET pulse. STOP during programming must block restart even after release; recovery requires ON. SET while OFF must program/read back the target without enabling outputs. The explicit reset request remains unchanged. |
| Interrupted commands | Interrupt Pico execution at each ON/OFF/SET/RESET transaction boundary and drop USB before the final response. Do not report success or replay commands automatically; verify readback identifies the actual retained/intermediate state and leaves it unchanged until explicit recovery. |
| Loop stability | Measure gain and phase for each fitted capacitor population and feedback scale. Use ≥45° phase margin and ≥10 dB gain margin as engineering review criteria. |
| Load transients | Apply measured current steps at the socket with 100 ns and 1 µs edge settings and 10, 20, 50, and 100 µs pulse widths. Record actual edge rate, droop, overshoot, recovery, and repetition rate. |
| Explicit reset | Test local, remote, and U903-commanded reset; simultaneous requests; Pico absent/unprogrammed; disconnected remote cable; and remote-source power loss. With valid VIO and no request, confirm J1.54 is low. U903's last explicit request must persist through Pico power loss/reboot; each request independently asserts reset, and releasing one cannot override another. Keep the external clock running during intentional reset pulses. |
| Reset independence | With VIO held valid, vary CORE_PG, IO_VALID, VIN12_VALID, and RUN_LATCH and exercise ON/OFF/SET and warnings. Confirm none of these generates a reset request. Capture actual J1.54 during supply ramps as well; distinguish analog behavior during invalid VIO from deliberate logic-controlled reset. |
| Telemetry | Calibrate voltage, shunt readings, zero-current offset, and U904 AIN0/AIN1 ratiometric temperature readings, including ADC loading of the 100 kΩ NTC network. Verify addresses 0x10/0x20/0x40/0x41/0x48 and read-only attachment. Record instrument settings and temperature. |
| Control bus | Establish board-side capacitance ≤80 pF and measure SDA/SCL low levels, rise times, noise and ground offset at every receiver. Verify U903 junction temperature remains ≤100°C throughout the qualified load/airflow envelope; its SDA current allowance above 100°C is incompatible with the present 2.2 kΩ pullups. The remote U1001 temperature alone does not establish this limit. |
| Functionality | Establish power and clock, explicitly reset the DUT, load and execute one kernel, and compare its output. Capture supply behavior at kernel start and completion. Include nominal operation and selected low-voltage and boost points. |
| Steady power | Run the kernel in a large back-to-back loop, allow electrical and thermal readings to settle, and collect averaged Core/I/O voltage, current, and power. Record warning status and airflow; distinguish board/socket supply power from die power and account for downstream board loads. |
| Sustained operation | Run selected operating points for eight hours, logging resets, errors, supply extrema, current, temperature, and airflow. |

Choose pulsed-load amplitude and duty cycle within the configured input, current, and thermal limits. The 10 A continuous target is not an instantaneous current clamp or a required load at every voltage. Numerical droop acceptance limits are not assigned; use the measurements to assess board delivery and the observed ASIC operating region.

Measure rising and falling load edges. Trigger actual ASIC captures on the single functionality kernel's start and completion and on transitions into or out of the power loop. Supplemental qualification can vary idle intervals. Probe socket power and ground locally and document bandwidth and probe loading. INA226 telemetry is intended for steady averaged power; it does not establish the minimum transient voltage or capture every pin event.

## Test record

Each record should identify the board and DUT, hardware revision, fitted capacitor population, controller revision, register readback, clock settings, input wiring, load waveform, probe locations, instrument configuration, and temperature. Attach the waveforms supporting supply extrema and reset events. Keep board-side observations separate from inferred die behavior.
